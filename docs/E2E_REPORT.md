## Important seed caveat

- ❌ Running the seed a second time against the same DB is not idempotent: it fails immediately with `SQLITE_CONSTRAINT_UNIQUE: organizations.slug` for `demo-plumbing-co`. A fresh DB seed succeeds. Recommendation: make seed reset/UPSERT the demo organization (and related fixtures), or document that the seed requires a fresh database.
- The pre-existing seed hash for `owner@demoplumbingco.com` did not validate against `password123` during login verification, so the seeded demo org could not be used for authenticated endpoint checks. Registration-created user authentication works correctly. Recommendation: generate the fixture password hash using the same bcrypt runtime during seeding and document the demo credentials.
